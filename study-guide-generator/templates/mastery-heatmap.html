{#- Truncate at 10 rows - legibility ceiling; the manual's "typically 6-10" is guidance, not a hard cap the template enforces by rejecting more, so anything beyond 10 is dropped from the visible table and surfaced as a footnote instead, never silently. #} {%- set all_topics = topics | default([]) %} {%- set shown_topics = all_topics[:10] %} {%- set truncated_count = (all_topics | length - 10) if (all_topics | length > 10) else 0 %} {#- status_class(): "In Progress" -> "In-Progress" so it forms a valid single CSS class token - the space in the raw value can't be used directly as a class name. #} {%- macro status_class(status) -%} status-{{ status | replace(' ', '-') }} {%- endmacro %} {#- date_serial(): a plain day count for one date string, or the empty string when the value is not a date at all ("TBD", "Not tracked", blank, a quarter label). Subtracting two serials gives the number of days between them, which is all the two delay columns need. Why this is done in the template rather than through the days_between() Jinja global: days_between only accepts DD-MMM-YY, DD-MMM-YYYY and YYYY-MM-DD. Real workplan trackers also hand us DD/MM/YYYY, which real exports do, and a date the parser cannot read is indistinguishable here from a date nobody tracked - which is exactly the confusion the fallback below has to resolve. Parsing in one place, with one placeholder rule, keeps "is this a real date" and "how far apart are these two dates" from ever disagreeing. The global is still registered by render_slide.py; this template no longer calls it. Accepted separators are "-", "/", "." and space, so 17-Aug-26, 17/08/2026, 17.08.2026, 2026-08-17 and 17 Aug 2026 all parse. Month may be a number or a three-letter name. Two-digit years follow strptime's %y rule (00-68 -> 20xx, 69-99 -> 19xx). Numeric dates are read DAY FIRST, matching the DD-MMM-YY house format; a first field above 12 with a second field of 12 or under is swapped, so an unambiguous US-ordered date still parses rather than falling through to the not-a-date branch. A month above 12 or a day above 31 returns empty rather than a wrong number. The day is bounded at 31 only, not at the real length of its month: 30-Feb-26 therefore parses (as 2 March) rather than being rejected, which keeps the stated date visible in the cell instead of being replaced by the current-date fallback below. The arithmetic is the standard Julian-day-number formula, which needs only integer division - Jinja has no date type, but it does have `//`. #} {%- macro date_serial(value) -%} {%- set s = (value | default('') | string) | trim -%} {%- set parts = s.replace('/', '-').replace('.', '-').replace(' ', '-').split('-') | select | list -%} {%- if (s | lower) not in ['tbd', 'tba', 'n/a', 'na', 'none', 'not tracked', 'not stated', 'unknown', '-', '–', '—'] and parts | length == 3 -%} {%- set months = {'jan': 1, 'feb': 2, 'mar': 3, 'apr': 4, 'may': 5, 'jun': 6, 'jul': 7, 'aug': 8, 'sep': 9, 'oct': 10, 'nov': 11, 'dec': 12} -%} {%- set iso = (parts[0] | length == 4) -%} {%- if iso -%} {%- set d_raw = parts[2] -%}{%- set m_raw = parts[1] -%}{%- set y_raw = parts[0] -%} {%- else -%} {%- set d_raw = parts[0] -%}{%- set m_raw = parts[1] -%}{%- set y_raw = parts[2] -%} {%- endif -%} {%- set m_key = (m_raw | lower)[:3] -%} {%- set m0 = months[m_key] if m_key in months else (m_raw | int(default=0)) -%} {%- set d0 = d_raw | int(default=0) -%} {%- set y0 = y_raw | int(default=0) -%} {#- Day/month swap for an unambiguously month-first numeric date (08/17/2026). Never applied to the ISO form, whose field order is not in doubt: a month of 13 there is a bad date and must fail, not be silently reinterpreted as a day. -#} {%- set d = d0 if (iso or m0 <= 12) else (m0 if d0 <= 12 else 0) -%} {%- set m = m0 if (iso or m0 <= 12) else (d0 if d0 <= 12 else 0) -%} {%- set y = (2000 + y0) if y0 < 69 else ((1900 + y0) if y0 < 100 else y0) -%} {%- if m >= 1 and m <= 12 and d >= 1 and d <= 31 and y >= 1900 -%} {%- set a = (14 - m) // 12 -%} {%- set yy = y + 4800 - a -%} {%- set mm = m + 12 * a - 3 -%} {{- d + ((153 * mm + 2) // 5) + 365 * yy + (yy // 4) - (yy // 100) + (yy // 400) - 32045 -}} {%- endif -%} {%- endif -%} {%- endmacro %} {#- delay_cell(): Delay Since Last / Delay Since Original are NEVER authored by hand - always computed from the row's own dates (see the topic loop below, which does the subtraction) and passed in here as a day count. Renders "TBD" rather than a number when `days` is none, which happens only where the CURRENT due date itself is not a real date and there is therefore nothing to measure against. A missing original or last due date no longer produces TBD: it resolves to the current date and the delay computes as 0. #} {%- macro delay_cell(col_class, days) %} {%- if days is none %} TBD {%- else %} {{ days }} {%- endif %} {%- endmacro %}

A topic with no recorded review history has not slipped, so where original or last due date is absent, blank or a placeholder, it resolves to the CURRENT due date and the corresponding delay computes as 0.
