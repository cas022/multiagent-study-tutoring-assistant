{#- Continuous density calculation - see the CSS comment above the table{font-size:...} rule for the reasoning. Solves for a font size that makes (row_count + ~1.5 for header/summary, or ~0.75 for the header alone where the optional summary row is absent) rows fill a target budget, then clamps to a 7-12px range so a low-row-count slide doesn't blow up into a cartoonishly large, deck-inconsistent font just because it has the vertical room. Padding scales proportionally with the resulting font size instead of being picked separately. The budget is 480px of chrome-free height LESS whatever the footnote lane takes. That subtraction is new. The 480px figure was previously described as carrying a safety margin so "a multi-line footnote never collides with the last row" - a margin, not a reservation, and it did not hold, because the footnote lane was an absolute overlay that the table could render straight through no matter what the budget said. The lane now sits in normal flow (see the .footnotes rule above), so its height is genuinely unavailable rather than notionally avoided. Reserve is estimated at 10px/1.4 line-height over an ~1168px lane width, plus the lane's 12px top margin, capped at the CSS max-height.
